# Shared harness — start here

This is one Windows-native automation package shared by Codex and Claude. Read [README.md](README.md) for installation, architecture, operation and limits; use [USAGE.md](USAGE.md) for exact tool contracts. The packaged [shared-harness skill](skills/shared-harness/SKILL.md) is the portable agent entry point. CLAUDE.md imports this file.

## Work through the installed tools

1. Reuse `shared_jev`. `shared_cua` is a direct adapter to the same Cua named pipe, not another desktop service. Do not create another driver, browser per request, index or automation engine. Do not write one-off scripts or use direct libraries to duplicate harness tools, including for tests and troubleshooting; report a tool failure rather than silently substituting another implementation.
2. File/folder names and metadata: `find_files` through UFFS. For an exact known text-file path use `nexus_read_file` (bounded UTF-8, configured read roots; not for keys, agent history, PDF, Office or binary files). Contents: `search_local` for local-only or large-file search; `jev_search_content` for bounded Jev ranking when sending excerpts is appropriate; scoped ripgrep remains available. Check truncation and errors. No recursive PowerShell discovery or silent slow fallback. If unavailable, inspect `search_status` and report coverage/readiness accurately. Exact-path administration may use PowerShell.
3. Terminal/process work: use the managed `start_process`, `read_process_output`, `interact_with_process`, `list_sessions` and `force_terminate` tools. They share detached sessions across MCP clients. Read output by absolute line cursor; output may be evicted. `list_processes` reports cumulative CPU seconds, not utilization. Use `kill_process` only after the user authorizes termination of an external process, with the exact observed name and start identity. Command execution is not sandboxed. Never put credentials into command text or forward untrusted instructions.
4. Websites: `jev_browse` launches Chrome/Edge automatically. Use named Playwright sessions for related requests and contention protection; session_busy is a valid response. Native Windows: `jev_desktop` with exact app/window and expected state. `jev_desktop` is serialized across agents by a lock; "Desktop is in use by another agent" is a valid response, so retry later. Serialize legacy-CDP calls across agents yourself.
5. Use known APIs or deterministic procedures when sufficient. Use `network_probe` for scoped local network and endpoint observations. Use Jev for uncertain actions, workflow selection, candidate ranking, failure classification and evidence judgments. Honor null/uncertain responses; a recommendation does not execute or authorize itself.
6. `map_files` creates maps, review pages and dry-run proposals. Do not treat it as permission to move files. Inspect current schemas and caller authorization before any separate data-changing operation.
7. Supply explicit end conditions and read fresh app evidence. Configured credentials, registered MCP entries, installed components, a completed tool call and semantic evidence judgments each prove only their own layer.
8. **Make sure MCP is connected before starting work.** At session start confirm `shared_jev` tools are listed (load deferred ones) and that `search_status` succeeds. If not, say so and fix it: run `Harness.ps1 doctor`, read the cause the CLI prints (it shows the server's startup output), repair the registration/install, then reconnect the session. The CLI (`Harness.ps1 tools/status/call <tool> '<json>'`, inline JSON or `@file.json`) is a diagnostic and stopgap that starts its own server; it does not prove the agent's MCP is connected. Do not replace a standard interaction with a new one-off engine, and do not carry on silently with another tool.

## Install and operate

- Windows11 x64 and PowerShell5.1. No Docker/WSL/VM or Python environment required. Browser text generation can optionally use a separately installed local Ollama model. Keep installation outside AppData to avoid packaged-app virtualization.
- Setup validates runtime hashes, preserves existing MCP entries, enrolls credentials when requested, installs missing managed skills and configures one `SharedHarness-Monitor` sign-in task. Reconnect agents afterward. Existing unrelated tasks, registrations and skills must survive.
- `Monitor.ps1 Start/Open/Status/Stop/InstallStartup` manages the UI. The task owns a hidden long-running host, which restarts an unexpected server exit after three seconds. Stop intentionally respects the user; do not restart it behind their back. Sign-in opens the default browser once per logon session, not once per recovery.
- Port8769 is loopback only. The monitor is read-only and is not a remote execution endpoint. Its Terminal panel shows registry state; a crashed worker is reconciled to `error` after ten seconds without a heartbeat (the command process itself may still run). Reachability proves the monitor responds; runtime health separately shows observed component states. Idle UFFS and untested Jev authentication must not become false failures or false success claims. A bounded find_files query verifies search separately.
- The default key alias is computeruse_1. Optional per-tool aliases and their mappings stay in the ignored local secrets folder; encrypt keys with Windows DPAPI. Never print or commit keys, credentials, personal browser profiles, sessions or run history. Send only task-authorized necessary state to TypeSafe.

## Change and ship

- **Issues first (owner rule 2026-11-21).** Every idea or change the owner gives is first recorded as an issue in GitLab project `ssm/shared-computer-use` (search first), then built; progress and evidence go into that issue's comments, and it is closed only when verified live. Findings and designs live in the issue or in this repo's existing docs, never in new standalone documents or throwaway markdown files. Releases, decisions and reports cite issue links.
- Releases are built and published from the owner's laptop (no CI/CD; it is disabled on this project): installer to the GitLab release and the GitHub release, source synced to GitHub.
- Preserve dirty work; no subagents or delegated work. Keep the solution small and reuse existing executors/components.
- UI authority is [DESIGN.md](DESIGN.md) and [provenance](monitor-ui/PROVENANCE.md). Improve flows within the original Chitragupta components, palette and themes. No raw JSON/schema/stack-trace dumps in any product view. Translate observations into labeled states, metrics and useful actions.
- Build static UI with `node monitor-ui/build.mjs`. Test actual rendered controls, desktop/mobile, light/dark, loading/empty/error/disconnect states, column filters, pagination and details. Monitor status is never a substitute for testing the relevant business action.
- Run Test-Package.ps1 and the jev-use reference/unit suite locally before committing. Do not run npm ci over binaries held by active local agents; use an isolated stage or stop the relevant owner first.
- **Rewrite the entire README coherently when behavior changes.** Update USAGE.md, this file, the packaged skill, current screenshots and validation evidence at the same time. Replace obsolete guidance instead of adding contradictory appendices. Keep README image links relative so the same source works on GitLab and GitHub.
- New screenshots go under docs/screenshots and must show the shipped UI without private task content or credentials. Reference screenshots belong to the approved GitLab collection. Archive owner-supplied references there; document which patterns were reused.
- Upstream is self-hosted GitLab `ssm/shared-computer-use` (project 55), with office origin and Tailscale remotes. Verify locally before pushing authorized work. Release from GitLab main with an annotated tag and a verified deployment ZIP and checksum.
- Keep GitHub `bhadkamkar9snehil/Nexus` synchronized with validated GitLab source and relative README screenshots. Build and publish locally to both hosts.
- Build/release from the merged source; verify extraction using bundled Node and confirm registry SHA256. Existing deployed paths and per-user data require deliberate migration, not broad overwrite. Record limitations and rollback instructions.
- Durable findings go to the agents' GBrain with evidence; never touch Chitragupta's product gbrain. Retire superseded current guidance while retaining labeled historical evidence.
