Overview uses six compact measured instruments. Activity bars have hourly buckets; pass raster represents finished calls; duration ticks encode actual sample distribution; decision bars show calls; token split shows input/output composition; spend bars compare actual per-tool estimate. No invented budget, trend percentage or targets. Workload composition and duration histogram use the same recorded window.

Runs have a380px maximum internally scrolling body, sticky labels/filter controls, local column predicates, sorting and10/20/50-row pagination. A row opens readable labeled details. Search, filters and sort operate on the bounded server log tail. Unknown values remain missing, not zero.

Capabilities use agent registration rows, category tabs, search, a scrollable list and a readable parameter table with observed call statistics. Health uses separate monitor, startup, desktop, browser, search and Jev panels. Healthy/ready/configured/idle/attention are distinct, not synonymous with end-to-end success.

The Windows desktop app is the only product UI. The hidden loopback runtime does not launch a browser. Windows Task Scheduler owns the hidden host; that existing host recovers a server exit after three seconds without a separate watcher process. Intentional stop remains stopped. Product UI never displays a wire schema, stack trace or raw JSON; docs may show purposeful invocation/configuration examples.

Observability is a dedicated desktop route. It shows the recorded call overview, selectable time window, synchronized waterfall, category and status filters, pause/resume, sortable call list, and call inspector. Timing uses actual wall-clock starts and measured durations; overlaps do not imply causal links. The inspector shows host-reported MCP client identity, request and response field shapes, byte counts, preparation/executor durations and bounded reported model response samples. It never stores payload values. Unknown or unreported fields remain unknown. The server caches the parsed run log and uses conditional HTTP; the page does not start tool catalog or health probes when opened directly. The data source is the existing bounded run log. Overview retains its compact recent-runs table for now.

File transfers use the existing MCP transport. The inspector records direction, verified decoded byte count and execution duration; it never records binary contents, credentials or file paths. The 256 KiB inline limit bounds both transfers and context cost. Large out-of-band transfers require a separately configured and authenticated HTTPS data plane.

Agent communication telemetry records authenticated peer send/receive, delivery or refusal, responder queue and execution durations, outcome, message byte count, hop and trace/span IDs. It never retains subjects, bodies or authentication tokens in the run log. MCP calls initiated in a responder inherit context when their host passes it to the MCP process. The local view does not collect remote logs. MCP calls and peer spans are separate counts; avoid counting a nested peer operation as an extra MCP call.

Research direction (2026-11-26): follow the official MCP files draft for inline and future authenticated HTTPS transfer, A2A task/message/artifact lifecycle for interoperable peer work, and OpenTelemetry GenAI MCP trace context. Desktop Commander and MCP filesystem reference suggest bounded metadata, batch read, directory operations, cancellable search and safe audit queries. Playwright MCP suggests console/network diagnostics from the existing named browser session.
